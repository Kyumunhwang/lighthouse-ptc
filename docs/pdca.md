# PDCA (Plan-Do-Check-Act) Development Framework

## 1. Plan (기획 및 설계)
* **목표:** 동시성 문제가 없는 완벽한 예약 시스템 아키텍처 설계.
* **액션:**
  1. Google Sheet에 `reservations` 시트 추가 (컬럼: Timestamp, Email, Student, Parent, Teacher, Option, Time, Status).
  2. 시스템 아키텍처 다이어그램 및 UI 와이어프레임 확정.
  3. 로그인 계정 이메일과 `roster` 시트 내 학부모 정보를 어떻게 매핑할 것인지 인증 로직 설계 (예: 로그인 후 '자녀 이름'과 '부/모 이름' 입력하여 크로스 체크).

## 2. Do (구현 및 실행)
* **목표:** MVP(Minimum Viable Product) 개발.
* **액션:**
  1. **Phase 1:** Google Apps Script Web App 설정 및 데이터 읽기(GET) API 구현.
  2. **Phase 2:** 프론트엔드 UI(학부모 예약화면, 교사화면, 관리자화면) 구현.
  3. **Phase 3:** 예약 쓰기(POST) API 및 `LockService` 기반의 중복 예약 방지 로직 구현.
  4. **Phase 4:** 예약 완료 Slip 생성 및 Admin/Teacher 뷰 데이터 바인딩.

## 3. Check (검증 및 테스트)
* **목표:** 극단적인 상황(Edge Cases)에서의 시스템 무결성 확보.
* **액션:**
  1. **동시성 테스트:** 동일한 교사/시간 슬롯에 두 명의 유저가 1초 간격으로 예약 버튼을 눌렀을 때, 한 명은 실패 메시지를 받고 한 명만 성공하는지 확인.
  2. **제한 테스트:** 한 학부모가 5개 이상의 상담 옵션을 선택하려 할 때 UI에서 완벽히 차단되는지 확인.
  3. **권한 테스트:** 학부모 계정으로 로그인 시 교사나 운영자 뷰(Dashboard)에 접근할 수 없는지 검증.
  4. **데이터 정합성:** 다자녀(형제/자매) 학부모가 각 자녀별로 정상적으로 예약을 분리해서 할 수 있는지 테스트.

## 4. Act (개선 및 배포)
* **목표:** 피드백 수용 및 실제 PTC 기간 운영 준비.
* **액션:**
  1. 발견된 버그(UI 깨짐, 로딩 지연 등) 수정 및 코드 리팩토링.
  2. 최종 버전 배포 전, 교무실 내부 교사들을 대상으로 클로즈 베타 테스트 진행.
  3. 학부모 대상 '예약 시스템 사용 가이드' 문서(또는 영상) 제작 후 안내 페이지에 링크 연동.
